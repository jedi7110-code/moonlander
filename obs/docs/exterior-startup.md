# オープニングと船内の読み込み順序

2026-10-13。オープニングを船内の読み込み待ち時間として使う。

2026-10-15の採用版は、母艦Bのパネルをロゴ再生開始前に組み立ててシェーダーを準備する。
小型船Aの濃い線は、従来通り遅延読み込みした探査機へ適用し、その後にGPU準備する。
船内・探査機の先読み開始通知とロゴの時間設定は従来の順序を保つ。

同日のローカルOBS入口で、再生開始1453.1ms、船内組み立て開始5035.8ms、準備完了18672.2msを確認。
冒頭38秒の最大フレーム間隔は67.5ms、ロゴの段階飛びは0。船内読み込み中には短い落ちが残り、準備後は約60fpsで再生。

1. OBSの軽い起動コードが宇宙背景とオープニングのiframeを表示する。
2. 映像側は母艦だけを作り、ロゴ画像のデコードと母艦のシェーダー・初回描画を準備する。
3. 映像を開始し、動いているフレームを2回表示してから `playing` を親へ通知する。
4. 親側は船内の先読みヒントを有効にし、アセットのネットワーク取得を開始する。
5. ロゴの10段階表示が完了した3.6秒以降、2フレーム表示して `logo-resolved` を親へ通知する。船内コードの評価と、分割したモデル解析・組み立て・GPU準備をロゴの保持中から始める。
6. ロゴが完全に消えた7.4秒以降、2フレーム表示して `intro-finished` を親へ通知し、探査機を準備する。
7. 船内が準備できても映像は続き、ユーザーの操作で船内へ入る。

船内の部屋・設備の組み立ても一つの長い処理にせず、各段階の間に描画フレームを渡す。同期のスタディ用ビルダーと同じ生成処理を使い、形状・配置・操作対象を維持する。

HTMLの船内先読みリンクは、開始前にリクエストされないよう不活性なtemplateに入れている。外観の形状定数は船内モデルの作成コードから分離した。母艦から船内キャラクターや探査機へ静的な読み込み依存を持たせない。

探査機の読み込みが極端に遅い場合、探査機が入るディゾルブの先頭で映像時刻を待たせる。準備後に同じ時刻から続け、途中から突然現れないようにする。途中の時刻へ直接シークした閲覧では、最初の描画前に探査機も準備する。

確認用の時刻はhtmlのdatasetに保持する。親の `openingStartedMs` → `cabinLoadStartedMs` → `openingLogoResolvedMs` → `cabinBuildStartedMs` → `cabinReadyMs`、映像の `shipReadyMs` → `filmStartedMs` → `introFinishedMs` → `probeLoadStartedMs` → `probeReadyMs`。親とiframeの数値はそれぞれのページの起動時刻を基準にするため、異なるページ間で直接比較しない。

`logoPlayback` はロゴ表示中の最大フレーム間隔と、10段階の表示で飛ばした段階数を記録する。ロゴの出方・保持・フェードの設定は変えない。

ローカルのOBS本体で、親の再生開始通知約1.33秒、船内読み込み開始約1.33秒、その準備完了約12.84秒を確認。段階的な組み立てを加えた後のキャッシュ済みの再確認では、再生開始・船内読み込み開始約1.64秒、船内準備完了約6.52秒だった。どちらも再生を続けた状態から船内へ切り替えて表示を確認した。読み込み時間は端末とキャッシュによって変わる。

ロゴとモデル準備の重なりを除く前後を同じOBS入口で確認。変更前は最大フレーム間隔1950.6ms・7段階の飛び、変更後は17.7ms・段階飛び0だった。変更後の親側時刻は、先読み開始1233.8ms、重い準備開始8625.2ms、船内準備完了12397.0ms。映像側の探査機準備開始はロゴ消失後の8502.7ms。これらはローカルの一回の計測値で、配信環境・端末・キャッシュによって変わる。

## 母艦登場時の負荷分散

ロゴ消失後へ一括で準備を移した状態では、母艦登場中に最大1783.7ms、初回描画に765.9msのフレーム停止を確認した。開始を遅らせるだけでは、停止する場所が移る。

- 船内、Miloの頭・体・髪、Lucyの補正・足裏・走行用スキン、ロボットのアトラス・機体を、同期スタディと共通の生成ステップに分割する。小さいステップは約4msの枠にまとめ、枠の間に2回のrequestAnimationFrameを挟んで映像に描画機会を渡す。
- シェーダーは場面全体を一度にcompileAsyncへ渡さず、約4msの提出バッチに分割する。クリッピング面数と影用プログラムは維持する。
- テクスチャの画像変換はImageBitmapへ非同期で行い、GPU転送を画像ごとに分ける。色空間・上下方向・アルファ処理は元の設定に合わせる。
- 最初の完全描画の前に、実際の船内シーンで8オブジェクトずつ描画して、ジオメトリ・VAO・プログラムの初回準備を分散する。
- Lucyの未変更モーフ配列を複製せず共有し、不要なモーフの全コピーや、Miloの材質コピーで発生していたTextureのJSON画像エンコードをなくす。

`openingFrames`は冒頭38秒の各秒ごとの最大フレーム間隔、フレーム数、50ms超の回数を記録する。`cabinAssemblyMs`と`cabinTextureUploadMs`は準備バッチと転送の実測時間。端末の差を確認するための診断値で、演出の時間設定には使わない。

最終のキャッシュ済みOBS入口の通し再生では、冒頭38秒の最大フレーム間隔66.7ms、ロゴの段階飛び0。船内準備開始4694.9ms、準備完了18786.0msだった。変更前の1783.7msから長い停止を減らしたが、約50〜67msの短いフレーム落ちは残る。この一回のローカル計測は、OBS本番の端末やネットワークで同じ値になる保証ではない。船内への手動切り替えと照明起動も確認した。
