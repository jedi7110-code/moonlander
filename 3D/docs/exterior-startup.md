# オープニングと船内の読み込み順序

2026-10-13。オープニングを船内の読み込み待ち時間として使う。

1. OBSの軽い起動コードが宇宙背景とオープニングのiframeを表示する。
2. 映像側は母艦だけを作り、ロゴ画像のデコードと母艦のシェーダー・初回描画を準備する。
3. 映像を開始し、動いているフレームを2回表示してから `playing` を親へ通知する。
4. 親側は船内の先読みヒントを有効にし、アセットのネットワーク取得を開始する。
5. ロゴが完全に消えた状態を2フレーム表示してから `intro-finished` を親へ通知する。この後に船内コードの評価・モデル解析・組み立て・GPU準備と、探査機の準備を始める。
6. 船内が準備できても映像は続き、ユーザーの操作で船内へ入る。

船内の部屋・設備の組み立ても一つの長い処理にせず、各段階の間に描画フレームを渡す。同期のスタディ用ビルダーと同じ生成処理を使い、形状・配置・操作対象を維持する。

HTMLの船内先読みリンクは、開始前にリクエストされないよう不活性なtemplateに入れている。外観の形状定数は船内モデルの作成コードから分離した。母艦から船内キャラクターや探査機へ静的な読み込み依存を持たせない。

探査機の読み込みが極端に遅い場合、探査機が入るディゾルブの先頭で映像時刻を待たせる。準備後に同じ時刻から続け、途中から突然現れないようにする。途中の時刻へ直接シークした閲覧では、最初の描画前に探査機も準備する。

確認用の時刻はhtmlのdatasetに保持する。親の `openingStartedMs` → `cabinLoadStartedMs` → `openingIntroFinishedMs` → `cabinBuildStartedMs` → `cabinReadyMs`、映像の `shipReadyMs` → `filmStartedMs` → `introFinishedMs` → `probeLoadStartedMs` → `probeReadyMs`。親とiframeの数値はそれぞれのページの起動時刻を基準にするため、異なるページ間で直接比較しない。

`logoPlayback` はロゴ表示中の最大フレーム間隔と、10段階の表示で飛ばした段階数を記録する。ロゴの出方・保持・フェードの設定は変えない。

ローカルのOBS本体で、親の再生開始通知約1.33秒、船内読み込み開始約1.33秒、その準備完了約12.84秒を確認。段階的な組み立てを加えた後のキャッシュ済みの再確認では、再生開始・船内読み込み開始約1.64秒、船内準備完了約6.52秒だった。どちらも再生を続けた状態から船内へ切り替えて表示を確認した。読み込み時間は端末とキャッシュによって変わる。

ロゴとモデル準備の重なりを除く前後を同じOBS入口で確認。変更前は最大フレーム間隔1950.6ms・7段階の飛び、変更後は17.7ms・段階飛び0だった。変更後の親側時刻は、先読み開始1233.8ms、重い準備開始8625.2ms、船内準備完了12397.0ms。映像側の探査機準備開始はロゴ消失後の8502.7ms。これらはローカルの一回の計測値で、配信環境・端末・キャッシュによって変わる。
